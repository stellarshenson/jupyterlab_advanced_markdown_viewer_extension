3. **Task [Extended] - Reconciliation paradigm research** (v0.1.0): Researched how concurrent editing is solved and which paradigm fits an agentic tool rewriting a Markdown file while the user types<br>
   **Result**: Two background agents read primary sources - the operational transformation papers (Ellis and Gibbs 1989, Jupiter 1995, Sun and Ellis 1998), the CRDT literature, Fraser's Differential Synchronization (2009), diff3 (Khanna, Kunal and Pierce) - and the actual source of VS Code, Emacs, Vim, IntelliJ, CodeMirror, `jupyter-collaboration` and `jupyter_ydoc`. Conclusion: operational transformation is a category error here because the disk emits no positioned operations, and the CRDT already in JupyterLab is a category error as the reconciler because a `.md` file carries no character identifiers to converge with - it is the transport only. The fitting paradigm is Differential Synchronization: hold a shadow of the last text agreed with disk, diff shadow against the new snapshot, apply as positioned hunks, update the shadow unconditionally. Fraser's fuzzy patching is replaced with a three-way merge (base = shadow) because a wrong fuzzy match silently corrupts a document the user is reading. The Star Colonel's overlay intuition maps onto the shadow but the geometry differs - a shadow sits beside the view, not underneath, and carries no precedence rule. Survey finding: no mainstream editor merges into a dirty buffer; VS Code refuses with four guards, Emacs and Vim refuse, IntelliJ asks, and JetBrains declares a `ConflictResolution.MERGE` mode documented for AI agents that is not implemented. `jupyter-collaboration` overwrites silently and its tracker carries open data-loss issues; its `YUnicode.set` already diffs but two-way against the live document, which is the defect the shadow fixes. Wrote `docs/research-live-markdown-reconciliation.md`. Corrected four mechanism lines through `pm-tools` (hash-first detection, shadow, three-way merge, the `undoable` flag rather than tracked origins), added `ACC-APPLY-43` for shadow maintenance, and recorded the unresolved constraint that JupyterLab's `Context._contentsModel` is private so a merged document cannot be marked clean without saving, patching a private field, or accepting the File Changed dialog.
