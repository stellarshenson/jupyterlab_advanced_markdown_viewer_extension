2. **Task [Extended] - Acceptance criteria and sibling extension survey** (v0.1.0): Defined the visual and functional paradigm for live Markdown files as 42 acceptance criteria and surveyed the eight sibling Markdown extensions for conflicts<br>
   **Result**: A background agent read the sibling extensions (edit-at-content, export, github-alerts, insert-content, switch-tab-scrolling-fix, syntax-rendering-fix, viewer-toc-fix, paste-as-markdown) plus the refresh-view and colourful-tab extensions and found twelve collision points: three competing scroll authorities (the switch-tab guard's 100 ms interval, the TOC fix scrolling to the hash on every `rendered`, edit-at-content's scroll sync), edit-at-content's invariant that `.jp-RenderedMarkdown` child count equals the `marked` block count, the alerts parser wrapper that only runs through `IMarkdownParser.render`, insert-content's whole-document `setSource` bursts that look like external rewrites, export reading the file from disk, and refresh-view's `context.revert()` discarding unsaved edits. The paradigm therefore applies external content through `sharedModel.updateSource` in one tagged Yjs transaction, three-way merges against the last disk text keeping the user's lines on overlap, highlights with CodeMirror decorations in the editor and inline spans inside existing blocks in the viewer, and signals through `widget.title.className`. Filed through `pm-tools` into `docs/acc-crit-advanced-markdown-viewer.md` under categories DETECT, APPLY, HILITE, CUE, CONFIG and COMPAT; `docs/defects.md` seeded with the author roster; `pm-tools check docs --strict` clean. Four sibling changes recorded as COMPAT criteria: TOC fix hash gating, switch-tab guard signal, refresh-view dirty prompt, export reading the on-screen source.
